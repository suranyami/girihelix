# Handoff — girihelix, paused after the engine-types design

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
| --- | --- | --- | --- |
| A custom Credo check that silently enforces nothing | `GIRI002` (an `if`/`cond` ban) was written, loaded, had its `run/2` invoked with the correct relative filenames and `in_scope=true` for every engine file, and still reported nothing — including when it returned a **hardcoded** issue. It was withdrawn rather than shipped. `GIRI001` (the 800-line rule) uses the same wiring and has never been observed firing either. | advisory | **Before trusting any custom Credo check, prove it fires.** Plant a violation that *parses* and confirm `mix credo` reports it. A guard that cannot fail is worse than no guard, because it looks like enforcement. |
| Non-vacuity probes that are themselves invalid | The first two attempts to prove `GIRI002` could fail appended a function *after* the module's closing `end`. The file then did not parse, so there was no AST to walk — a false negative that cost two debugging rounds. | advisory | When probing an AST-based check, confirm the planted file still compiles (`mix format --check-formatted <file>` is a fast parse check) before concluding the check is broken. |
| `grep -c` chained into a cleanup sequence | `grep -c` exits **1** on zero matches, so `cmd && grep -c PATTERN && cleanup` silently skipped the cleanup and left a planted `if` in `engine/geometry/loose.ex`. | advisory | Never chain a mutating or cleanup step behind `grep -c`. Use `$(grep -c … | | true)` for the count and separate the restore, as a `trap … EXIT` or a plain `git checkout --`. |
| Long single-shot generation of a large document | Already recorded in the workspace notes and confirmed here: Plan 1a's 2,222-line plan was written in segments with lint checks between them, deliberately. A single long `Write` degrades into repetitive fragments. | advisory | Write large documents in sections, verifying each. |
